PR #88 — feat: implement Merkle Patricia Trie for state verification Medium Risk
👤 SIDDHANTCOOKIE · 2026-05-29
Problem
Flat key-value state storage cannot generate lightweight cryptographic proofs of state integrity.
Approach
Introduces a Merkle Patricia Trie (MPT) in minichain/trie.py to calculate root state hashes after transaction execution.
What Changed
  • Created minichain/trie.py implementing branch, extension, and leaf nodes
  • Integrated state root hash calculation into minichain/state.py
  • Added unit test suite in tests/test_trie.py
✓ Strengths
Provides Ethereum-compatible state root hashing for light client verification.
✗ Weaknesses
Slightly increases state mutation latency due to trie node re-keying on every transaction.
🔍 Outcome If Merged
Block headers store verifiable Merkle state root hashes for instant state auditing.
❓ Open Questions for mentor
  • Do we need state trie pruning to prevent memory growth over long chain runs?

PR #89 — feat: async WebSocket P2P node discovery & transaction relay Low Risk
👤 DEV_GURU · 2026-06-02
Problem
Synchronous TCP socket networking blocks on connection attempts and drops peers during network spikes.
Approach
Replaces raw TCP sockets with an asyncio WebSocket server (minichain/p2p.py) for non-blocking peer discovery and block broadcasting.
What Changed
  • Migrated P2PNetwork to websockets async protocol
  • Implemented automatic peer ping/pong heartbeats and transaction gossip relaying
  • Updated P2P network integration tests
✓ Strengths
Significantly improves network throughput, peer connection stability, and broadcast resilience.
✗ Weaknesses
Adds websockets dependency to the core package.
🔍 Outcome If Merged
MiniChain nodes maintain persistent, non-blocking P2P connections across multiple peers.
❓ Open Questions for mentor
  • Should max peer connections be capped to avoid memory exhaustion on light hosts?
